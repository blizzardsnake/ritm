# RITM — недельный разбор с телефона

В «Питании» и «Статистике» есть кнопка «Недельный разбор». Выберите период и нажмите «Сформировать отчёт». Отчёт объединяет выполненные тренировки, питание, вес тела и доступное восстановление; добавляет четыре предыдущие недели контекста.

## Бесплатный ИИ без ПК

В Android-приложении подключите «Бесплатный ИИ на телефоне» в настройках тренера и введите собственный ключ OpenRouter. На экране разбора показаны получатели и состав данных: программа, выполненные подходы и усилие, названия продуктов/порции/заметки, полнота рациона, вес и доступные данные выбранных источников часов, цели и ограничения. Подтверждение относится к этому отчёту и выбранному сервису; оно сбрасывается при новом отчёте или изменении подключения.

«Разобрать неделю» отправляет запрос прямо с телефона. Доплата и переход на платную модель не предусмотрены. Ограничение приложения — 10 запусков ИИ в день, совместно с исходным тренером; у сервиса есть собственные лимиты. Возможны недоступность подходящей бесплатной модели и отказ сервиса. Ожидание общего недельного запроса ограничено пятью минутами; его можно отменить. Запущенный запрос расходует попытку даже при ошибке. Запросы не выполняются по расписанию или без нажатия владельца.

Ключ хранится отдельно от журнала, отчётов и синхронизации. Ответ проверяется до сохранения. Ошибка, чужой профиль или неподдерживаемые изменения не меняют программу. Этот ИИ — модель выбранного сервиса; этот чат получает историю, когда владелец передаёт сюда отчёт.

## Выбор и применение

Рекомендации показываются обычными карточками: параметр, прежнее/предложенное значение, причина и основания. Переключатели позволяют выбрать часть предложений. Ни импорт файла, ни ответ ИИ автоматически не применяются.

Ниже показана фактическая следующая тренировка из штатного движка openGym. Изменение веса/подходов/повторений меняет будущую программу и создаёт одноразовую запись предписания. Она действует до первого сохранённого занятия, где выполнен рабочий подход с этой записью. Открытие и отмена занятия её не расходуют. Затем штатная прогрессия продолжает работать от фактически выполненных подходов. Разминка, односторонние упражнения и дополнительные техники используют исходные построители подходов.

Новая рекомендация по другому параметру того же упражнения сохраняет ранее принятые, ещё не выполненные значения. Ручная правка настроек упражнения делает старое одноразовое предписание неприменимым. Смена единиц требует нового анализа для прежних предложений и не переименовывает старые кг в фунты. Нельзя применять корректировку во время текущей тренировки или после изменения программы/истории, от которой зависит следующая нагрузка. В таком случае сформируйте свежий отчёт.

«История корректировок» сохраняет источник (импорт файла или сервис/модель), время, причины, выбранные параметры и исходные значения. «Отменить изменения» восстанавливает прежние параметры. При новой ручной правке или более поздней корректировке того же упражнения показывается конфликт; отмена целиком останавливается и ничего не перезаписывает. Сначала нужно разрешить конфликт. Уже выполненные тренировки и съеденная еда при применении/отмене остаются историей.

## Передача отчёта в этот чат и обратный файл

Можно выгрузить JSON отчёта и передать его вместе с просьбой: «Разбери тренировки, питание, вес и восстановление за выбранную неделю. Верни файл ritm-weekly-proposal версии 1 для загрузки в RITM». Поля связи берутся из отчёта; пересчитывать или придумывать контрольные суммы не нужно.

Файл ответа — один JSON объект. Пользователь выбирает его кнопкой «Загрузить рекомендации»; редактировать JSON в приложении не требуется. Пример структуры ниже содержит условные значения связи, которые аналитик заменяет точными значениями из переданного отчёта:

```json
{
  "format": "ritm-weekly-proposal",
  "formatVersion": 1,
  "id": "unique-review-id",
  "profileId": "exchange.profileId",
  "generatedAt": 0,
  "analysisHash": "exchange.checksum",
  "planHash": "exchange.payload.plan.fingerprint",
  "window": {"from": "YYYY-MM-DD", "to": "YYYY-MM-DD", "contextFrom": "YYYY-MM-DD"},
  "title": "Название разбора",
  "summary": "Выводы по фактическим данным",
  "limitations": ["Недостающие данные"],
  "changes": []
}
```

`generatedAt` — числовое время формирования ответа в миллисекундах UTC (для запроса из приложения допускается время исходного отчёта). `window` копируется целиком из отчёта. `id` уникален: повторная загрузка идентичного документа ничего не дублирует; другой документ с уже занятым ID отклоняется. Хранится последний исходный отчёт в приватной папке Android, поэтому можно вернуться позже и загрузить ответ. После формирования нового отчёта старый ответ ему не соответствует.

Разрешённые элементы `changes`:

| Поле | Упражнение | Питание |
| --- | --- | --- |
| `type` | `exercise` | `nutrition` |
| `routineId`, `exerciseId` | Точные ID из отчёта | Отсутствуют |
| `field` | `weight`, `sets`, `reps` для режима повторений | `kcal`, `protein`, `fat`, `carbs` |
| `unit` | `kg`/`lb` из отчёта; `sets`; `reps` | `kcal` или `g` |
| `value` | Конечное число; подходы/повторения — целые | Конечное число |
| `id`, `reason`, `evidence` | Уникальный ID, причина, массив ссылок на показатели/записи | То же |

Один параметр нельзя повторять. Технические границы: вес 0–1000 кг/0–2205 фунтов, подходы 1–30, повторения 1–1000, ккал 1–10000, Б/Ж/У 0–1000 г. Эти границы проверяют формат, а не назначают допустимую нагрузку конкретному человеку. Неизвестные поля/команды/типы, неверные единицы и нечисловые значения отклоняются. При недостатке данных `changes` может быть пустым.

## Как трактуются данные

Частично заполненный рацион передаётся как частичная сумма, а не суточное потребление. Полные дни с известными четырьмя значениями нужны для средних. Неизвестный сон и ношение часов не становятся нулями или подтверждённым сном. Общие и активные калории часов не складываются и автоматически не добавляются к цели еды. Нагрузка мышечных зон вычисляется исходной функцией openGym по рабочим подходам; оригинальные карты в статистике сохранены.
