# План питания: файл для обмена с нейросетью

В разделе «Питание» доступны «Создать план», «Загрузить план», «Вставить план», «Поделиться планом» и «Поделиться шаблоном для нейросети». Основной формат — UTF-8 JSON, `format: opengym-personal-meal-plan`, `formatVersion: 1`. Импорт показывает содержимое перед кнопкой «Сохранить план». План не записывает еду в дневник. «Записать съеденное» открывает обычную форму, где можно изменить фактическую порцию и время перед сохранением.

Начните с пустого плана, добавляйте приёмы и продукты постепенно. Пустой приём разрешён; его нельзя записать как съеденный до добавления продуктов. «Изменить приём в плане» открывает знакомый выбор продуктов и граммовки. «Редактировать JSON» позволяет менять расписание, название, заметки и цели. Цели плана применяются отдельной кнопкой.

## Инструкция для нейросети

Скопируйте этот запрос вместе с файлом шаблона или текущего плана:

> Составь или измени мой план питания в приложенном формате openGym Personal. Верни один валидный UTF-8 файл JSON без Markdown ограждений. Сохрани ID существующего плана и приёмов, если изменяешь их. Не назначай цели без сведений обо мне; неизвестные значения оставляй null. У продуктов КБЖУ указываются на 100 г, grams — масса съедаемой порции в граммах. Указывай raw для сырого/сухого продукта и cooked для готового; не смешивай их значения. Не придумывай состав продуктов: используй мою этикетку или обозначенный проверяемый источник, иначе null. Не включай секреты и поля, которых нет в шаблоне. Разрешены пустые days, meals и items, чтобы дополнять план постепенно.

Передайте нейросети свои предпочтения и исходные сведения в отдельном сообщении. У этого файла нет автоматической отправки в какую-либо службу.

## Поля

| Поле | Значение |
| --- | --- |
| format, formatVersion | `opengym-personal-meal-plan`, `1` |
| id | Необязательный стабильный ID. Экспорт приложения сохраняет его. |
| name, note | Название и необязательная заметка. |
| from, to | Необязательные даты `YYYY-MM-DD` или `null`. |
| targets | Дневные kcal, protein, fat, carbs; неизвестное `null`. |
| days[].weekday | `0` — каждый день, `1–7` — понедельник–воскресенье. |
| days[].date | Альтернатива weekday: конкретная дата. Её приёмы заменяют обычное расписание на эту дату. |
| days[].id, meals[].id | Необязательные уникальные ID внутри плана. |
| meals[].name, time, note | Название, время `HH:MM` или `null`, заметка. |
| meals[].items[].grams | Положительная масса порции; десятичная запятая тоже принимается. |
| items[].food | name, необязательные id/brand, basis `100g`, preparation raw/cooked/ready/label, nutrients с четырьмя показателями. |
| food.source | Необязательное происхождение: type, dataset, datasetSha256, fdcId, originalName, dataType, license, url, updatedAt, basedOn. |

Источники из загруженного файла являются сведениями его автора; приложение не подтверждает их автоматически. Неизвестные поля и неподдерживаемые версии отклоняются. Лимит файла — 2 МБ. При повторной загрузке того же ID обновляется один план. При отсутствии ID он определяется содержимым файла. Приложение сохраняет планы в общей резервной копии, синхронизирует версии и удаления.

Дополнительно поддерживается CSV с запятой/точкой с запятой и таблица TSV: `День;Приём;Время;Продукт;Граммы;Ккал100;Б100;Ж100;У100`. Значения КБЖУ необязательны. Для дней подходят «Каждый день», названия дней недели и `YYYY-MM-DD`. CSV с десятичными запятыми удобнее разделять точкой с запятой. Кавычки защищают разделители внутри названий.

Шаблон можно воспроизвести из исходников командой `node scripts/export-meal-plan-template.mjs PATH.json`.
