# Недельный анализ openGym Personal

Недельный анализ объединяет тренировки, питание, вес тела и доступные данные восстановления. Владелец получает объяснимые предложения, проверяет их и отдельно применяет к будущему плану.

## Способы передачи

Уточнение владельца от 2026-10-03: основной ИИ должен работать через интернет с телефона без включённого ПК. Для этого используется бесплатный OpenRouter с собственным ключом, фиксированным адресом, бесплатными идентификаторами моделей и нулевым пределом цены. Отправка общего отчёта требует отдельного подтверждения состава данных и получателя на экране недельного разбора. Настольный обмен ниже остаётся дополнительным способом, а не условием работы основного ИИ. Фоновый автоматический анализ включается только после отдельной настройки и проверки владельцем.

Ручной способ работает из APK сразу: «Отчёт для анализа» создаёт общий JSON и читаемую сводку, которые можно передать в этот чат. Отчёт содержит выбранную неделю и до четырёх предыдущих недель контекста.

Предлагаемый автоматический способ — обмен двумя папками между телефоном и компьютером. Телефон пишет снимки в `Documents/openGymPersonal/Exchange/Data`, компьютер читает их. Компьютер пишет предложения в `Exchange/Suggestions`, приложение читает их. Для переноса файлов предлагается Syncthing на компьютере и поддерживаемый Android Syncthing Fork; перед настройкой фиксируются проверенные версии обоих клиентов. Установка стороннего клиента на телефон и сопряжение устройств выполняются с участием владельца. [Актуальный Android форк](https://github.com/researchxxl/syncthing-android), [проект Syncthing](https://github.com/syncthing/syncthing)

Передаётся только выбранная папка openGym Personal. При отключённой сети файлы остаются на устройстве и передаются после восстановления связи. Компьютер должен быть включён для получения файлов и выполнения локального анализа. Уже имеющаяся синхронизация openGym со своим сервером сохраняется как другой доступный путь; постоянный сервер не требуется для ручного экспорта.

## Снимки и чтение

Файл обмена содержит версию формата, ID профиля, время формирования, границу включённых данных и контрольную сумму содержимого. Запись выполняется через временный файл и завершается только после успешного сохранения. Читатель отвергает повреждённый или частично перенесённый файл. Временная ошибка сохраняет предыдущий исправный снимок.

Существующий MCP интерфейс расширяется чтением питания, данных часов, качества записей и общего недельного отчёта. Дополнительно он умеет читать файл анализа из выбранной папки без обязательной серверной базы пользователей. Запрос профиля не может незаметно переключаться на другой ID.

Автоматический недельный запуск подключается только после проверки появления свежих данных на компьютере. Предлагаемое время — воскресенье в 20:00 по Москве. Расписание и способ передачи окончательно согласуются при настройке обмена. Если нового отчёта нет, анализ обозначает недостаток данных и не выпускает новую корректировку по старому снимку. Обычные неизменившиеся состояния не порождают повторные уведомления.

## Содержание анализа

Анализ получает фактически выполненные подходы и усилие, соблюдение плана, тренды веса тела, КБЖУ и полноту дней, доступные сон и активность. Цель тренировок и питания, оборудование и ограничения берутся из профиля либо отмечаются как неизвестные. При недостаточной истории запрашиваются недостающие данные, а уверенные выводы о прогрессе не имитируются.

Числовые сводки рассчитывает приложение; текст анализа объясняет их. Калории часов не считаются точным измерением потребности в еде и не добавляются автоматически к рациону. Предложение может менять будущие веса, подходы, повторения и цели КБЖУ. В каждом изменении есть причина, период наблюдений и ссылки на использованные показатели.

## Применение предложений

Предложение — проверяемый JSON документ с ID, ID профиля, исходным снимком и отпечатком плана, периодом анализа, объяснением и разрешёнными изменениями. Оно не содержит исполняемого кода. Неизвестные поля изменений, неверные единицы, нечисловые значения и предложения для чужого профиля отклоняются.

Экран показывает значения до и после и фактическую следующую тренировку, полученную штатным движком прогрессии. Поэтому изменённые веса не могут молча оказаться перекрыты последней тренировкой. Если план изменился после формирования предложения, оно отмечается как устаревшее и требует повторного рассмотрения.

«Применить» изменяет только выбранные будущие параметры, сохраняет исходные значения, автора, причину и время. Есть отмена принятого изменения; при новых ручных правках сначала показывается конфликт. Выполненные тренировки и съеденная еда остаются историей. Ответ ИИ сам по себе ничего не применяет.

## Проверки

Проверяются полный цикл снимок, анализ, импорт, просмотр, применение и отмена; чужой профиль; повреждённый файл; повторный импорт одного предложения; устаревший план; изменение единиц; отсутствие нового отчёта; неполный рацион; отсутствующий сон; совпадение предлагаемой нагрузки с экраном следующей тренировки. Автоматический канал принимается после фактической передачи файла с телефона на компьютер и обратно.
