# RITM — передача данных для анализа

Основной ИИ работает через интернет непосредственно с телефона: «Питание» или «Статистика» → «Недельный разбор». Настройте свой бесплатный OpenRouter, подготовьте отчёт, проверьте состав передаваемых данных и разрешите отправку. Включённый компьютер для этого не нужен. Ответ показывается как предложение; изменения применяются отдельной кнопкой.

Для передачи человеку или в чат: подготовьте отчёт и нажмите «Экспорт анализа JSON». Системное меню Android позволяет отправить файл выбранному получателю либо сохранить его. Читаемый отчёт экспортируется отдельно. Основной JSON содержит выполненные подходы и время тренировок, питание и полноту дней, вес тела, доступные данные здоровья, исходную программу, следующую тренировку, достижения и журнал корректировок. Отсутствующие значения остаются неизвестными; план питания не считается съеденной едой.

Обратная загрузка: «Импорт рекомендации» в недельном разборе принимает файл `ritm-weekly-proposal`, версия 1. Его профиль, контрольная сумма исходного отчёта и отпечаток программы должны совпадать. Подробный формат находится в `personal-weekly-review.md`. Сначала проверяются причины и значения до/после, затем отдельно принимаются выбранные изменения. Ответ, созданный для старого плана, требует нового отчёта. Редактировать JSON в интерфейсе не нужно.

## Дополнительный MCP на компьютере

Этот способ необязателен. Клиент MCP запускает `mcp/src/index.js` через Node. Передайте в его окружение:

```json
{
  "OPENGYM_ANALYSIS_FILE": "/absolute/path/analysis.json",
  "OPENGYM_PROFILE_ID": "ID из вашего отчёта",
  "OPENGYM_ANALYSIS_MAX_AGE_HOURS": "168"
}
```

В Windows используйте абсолютные пути и обычное JSON-экранирование обратных слешей. Существующая серверная база `db.json` в этом режиме не требуется. `OPENGYM_PROFILE_ID` рекомендуется задавать явно: заменённый файл чужого профиля тогда будет отклонён.

Четыре инструмента: `get_personal_report`, `get_nutrition_days`, `get_health_history`, `get_record_quality`. Они возвращают время, профиль, границу данных и сведения о свежести. Дневные инструменты могут выбрать меньший интервал внутри отчёта. Полный отчёт сохраняет первоначальный период и четыре недели контекста. Контрольная сумма проверяет целостность, а не личность автора файла; храните папку приватно.

Повреждённый файл, неподдерживаемый формат, чужой профиль, файл старше заданного срока или из будущего отклоняются. Каждый запрос заново читает файл, поэтому замена файла с прежней датой изменения не возвращает старую версию из кэша. Ошибка чтения не переписывает файл. Максимальный размер — 16 МиБ. Девять исходных инструментов по всей базе доступны в прежнем серверном режиме (`OPENGYM_DATA`/`OPENGYM_UID`); в режиме отчёта они явно сообщают об ограниченном периоде снимка.

Если позднее понадобится синхронизация папок, можно отдельно сопрячь телефон и компьютер: `Data` для отчётов с телефона, `Suggestions` для файлов предложений обратно. Отчёт сначала сохраняется на телефоне, затем передаётся вашим файловым клиентом; при отсутствии сети хранится локально. Постоянный доступ к выбранной общей папке и автоматическая фоновая публикация в этой версии не настроены. Приложение использует явный экспорт/системное меню и выбор файла при импорте.

Автоматическое расписание анализа пока не создаётся. Сначала нужно проверить фактическую передачу свежих данных и обратный импорт на вашем телефоне, затем согласовать время запуска и уведомления. Наличие тестового файла на компьютере не подтверждает канал с часами или телефоном.
